# Инструкция по запуску кластера MongoDB с шардированием, репликацией и кешированием в Redis

Данный проект демонстрирует развертывание высоконагруженной и отказоустойчивой архитектуры (Вариант 3):
1. **Шардирование** (2 шарда) — для горизонтального масштабирования данных.
2. **Репликация** (по 3 узла на каждый шард: 1 Primary + 2 Secondary) — для обеспечения высокой доступности.
3. **Кеширование через Redis** — для ускорения повторных запросов на чтение к популярным эндпоинтам.

---

## Шаг 1: Запуск инфраструктуры

Запустите все контейнеры проекта в фоновом режиме:

```bash
docker compose up -d
```

Перед переходом к инициализации убедитесь, что все сервисы (`configSrv`, `redis`, роутеры `mongos-1`/`mongos-2`, узлы шардов `shard1-X`, `shard2-X` и приложение `pymongo_api`) успешно перешли в статус `Running`.

---

## Шаг 2: Инициализация компонентов MongoDB

Выполните следующие команды в терминале для настройки реплика-сетов конфигурации и репликации внутри шардов. Команды автоматизированы с помощью синтаксиса Here Docs (`<<EOF`).

### 1. Инициализация Config Server
```bash
docker compose exec -T configSrv mongosh --port 27019 --quiet <<EOF
rs.initiate({
  _id: 'configReplSet',
  configsvr: true,
  members: [{ _id: 0, host: 'configSrv:27019' }]
})
EOF
```

### 2. Инициализация Реплика-сета Шарда 1
```bash
docker compose exec -T shard1-1 mongosh --port 27018 --quiet <<EOF
rs.initiate({
  _id: 'shard1ReplSet',
  members: [
    { _id: 0, host: 'shard1-1:27018' },
    { _id: 1, host: 'shard1-2:27018' },
    { _id: 2, host: 'shard1-3:27018' }
  ]
})
EOF
```

### 3. Инициализация Реплика-сета Шарда 2
```bash
docker compose exec -T shard2-1 mongosh --port 27017 --quiet <<EOF
rs.initiate({
  _id: 'shard2ReplSet',
  members: [
    { _id: 0, host: 'shard2-1:27017' },
    { _id: 1, host: 'shard2-2:27017' },
    { _id: 2, host: 'shard2-3:27017' }
  ]
})
EOF
```

> **Важно:** Подождите 5–10 секунд, чтобы внутри реплика-сетов распределились роли (Primary/Secondary), прежде чем подключать их к роутеру.

## Шаг 3: Регистрация шардов в роутере и настройка коллекции

### 1. Добавление реплицированных шардов в кластер через `mongos-1`
```bash
docker compose exec -T mongos-1 mongosh --port 27017 --quiet <<EOF
sh.addShard('shard1ReplSet/shard1-1:27018,shard1-2:27018,shard1-3:27018')
sh.addShard('shard2ReplSet/shard2-1:27017,shard2-2:27017,shard2-3:27017')
EOF
```

### 2. Включение шардирования для тестовой базы данных и коллекции
```bash
docker compose exec -T mongos-1 mongosh --port 27017 --quiet <<EOF
sh.enableSharding("somedb")
use somedb
db.helloDoc.createIndex({ _id: "hashed" })
sh.shardCollection("somedb.helloDoc", { _id: "hashed" })
EOF
```

### 3. Наполнение данными (>= 1000 документов)
Заполняем коллекцию `helloDoc` пакетом из 1000 документов. 
*Примечание: для успешной прохождения валидации Pydantic в схеме приложения обязательно должно присутствовать поле `age`.*

```bash
docker compose exec -T mongos-1 mongosh --port 27017 --quiet <<EOF
use somedb
var docs = [];
for (var i = 1; i <= 1000; i++) {
    docs.push({ 
        name: "doc_" + i, 
        age: Math.floor(Math.random() * 50) + 18, 
        createdAt: new Date() 
    });
}
db.helloDoc.insertMany(docs);
EOF
```

## Шаг 4: Контроль и проверка для ревьюера

Для подтверждения успешного выполнения всех критериев проверки выполните три теста:

### Тест 1. Проверка работы приложения, объема данных и реплик
Выполните команду `sh.status()` в mongos:
```bash
docker compose exec -T mongos-1 mongosh --port 27017 --quiet <<EOF
sh.status()
EOF
```
**Критерии успешности в выводе:**
* В базе данных зафиксировано **более 1000 документов**.
* Документы распределены по обоим шардам (секция `chunks` для `somedb.helloDoc`).
* Строки подключения шардов содержат по **3 реплики** (доказывает работу отказоустойчивости).

### Тест 2. Проверка работы кеширования Redis (Скорость ответа < 100мс)
Для проверки времени ответа выполните замеры с помощью утилиты `curl` к целевому эндпоинту `/<collection_name>/users` (в нашем случае `helloDoc`):

* **Первый (холостой) вызов:** Приложение идет напрямую в MongoDB, формирует кеш и записывает его в Redis:
  ```bash
  curl -o /dev/null -s -w "Время первого ответа: %{time_total}s\n" http://localhost:8080/helloDoc/users
  ```
  *(Время может составлять от 0.050s до 1.500s в зависимости от мощности сервера).*

* **Второй и последующие вызовы:** Приложение забирает готовые данные из оперативной памяти Redis без обращения к БД:
  ```bash
  curl -o /dev/null -s -w "Время повторного ответа: %{time_total}s\n" http://localhost:8080/helloDoc/users
  ```
  **Критерий успешности:** Время повторного ответа должно быть **меньше 0.100s (< 100мс)** (обычно составляет `0.002s - 0.008s`), что подтверждает корректную работу кеширования.
